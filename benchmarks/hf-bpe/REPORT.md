# 首轮 HF BPE 适配结果

本文保存首轮节点版本及中间布局的历史记录。当前紧凑实现的有限对比见 [COMPACT_REPORT.md](COMPACT_REPORT.md)，理论内存分析见 [MEMORY_LAYOUT.md](MEMORY_LAYOUT.md)。当前无 affix 路径已包含有限长度门控；下文较早阶段的条件和数据不代表当前实现。

逐条位置索引原型已实现，入口为 `BpeTrainer::train_vocab_indexed()`。现有测试中，ID 复用、特殊 token、alphabet、前后缀及长度限制与 HF 参考行为一致；尚未接入精确批次或 owner 并行。代码及复现说明见 [README](README.md)。

## 后续布局调整

当前代码已改为 Efficient BPE 原型的扁平 u32 端点语料、词表长度表及权重边界表。初始化直接写入语料，去掉中间 `Word`、`get_chars()` 数组和每字符 `prev/next/word` 节点。首次 ID 复用时才补充出现位置跨度表，保留 HF 中同 ID 不同物理跨度的行为。

布局调整后，`tk-train` 的 21 项默认配置库测试通过（含 1,500 个逐轮随机差分配置及独立 greedy oracle）；500 个 HF 稳定版最终模型、磁盘重载及编码对照通过，累计发生 287 次 ID 复用。生命周期测试增加了同 ID 两个出现位置分别具有跨度 2 和 1 的端点检查。

下文性能数据均为调整前节点版本的记录；当前布局没有重新进行性能测量，不据此宣称提速或 RSS 改善。语料主体每槽 4 字节（另含分隔槽）是存储结构事实，不是进程峰值内存结论。

## 单调性证明与本次优化

用户指出普通 BPE 的旧 pair 单调性后，独立 subagent 给出了边界隔离、独立重放及首次激活的完整证明，见 [PAIR_MONOTONICITY.md](PAIR_MONOTONICITY.md)。相同字符串必须对应同一 token，但数字 ID 已经分配不等于该身份已在语料中出现；预留 special ID 的首次激活不会破坏普通 BPE 的证明。此前将 ID 复用本身视为限制的解释过宽，人工中间状态也不足以证明普通轨迹可达。

代码现在对无非空前后缀、无长度门控的路径永久剪除低于 `max(1,min_frequency)` 的 pair，并允许预留 special ID 首次激活时继续使用每 ID 长度表和位置索引。新 pair 只在整轮计数聚合后剪枝。非空 affix 的确可能破坏前提：suffix `"a"` 的 `baaba` 会让已有 `(b,aa)` 从 1 增到 2；通用路径保留完整处理。

本次 23 项无默认 feature 的库测试通过，包含既有逐轮差分和两个新增定向回归；代码按证明条件经独立只读复核。没有追加真实语料计时；完整精确批次尚未实现，也未将本定理当作完整批次正确性证明。

## 兼容性

`tk-train` 的 21 项测试、`tk-encode` 的 27 项 BPE 测试通过。新增检查包含 1,500 个配置的逐轮 pair／频率／输出 ID 差分、250 个普通配置的独立 greedy oracle，以及 500 个配置与未修改 HF 0.23.2 的最终模型、保存重载和稳定版编码对照；后者累计发生 286 次 ID 复用。

`continuing_subword_prefix` 和 `end_of_word_suffix` 共用 HF 初始化。合并只剥离右 token 的 prefix，再按完整字符串确定 ID；长度由每 ID 表保存，通用复用路径使用出现位置跨度。长度门控或 affix 身份复用的通用路径遵循 HF 候选词集合和频率账本，支持旧 key 增频，不提前丢弃低频记录。普通路径的安全剪枝见上节。模型构造时按 HF 的规则保留重复 pair 的最后一次 rank。

同时修复了现有 v1 编码器在单字符直接命中时绕过 suffix 的问题。随机稳定版核验检查的是训练输出及稳定版读写；整个 v1 推理栈的任意配置不在该验证结论内。部分随机小词表曾触发既有 `ptr_hash` 构建失败，本轮未扩展到加载器问题。

## 性能

本轮矩阵过大：14 组配置、三个实现、三次重复，共 126 次真实语料训练，约 288 秒。全部完成且每组完整模型摘要相同。保留原始记录，不追加测量；运行脚本的默认配置已收敛为 12 次小样本训练，并在开始前打印总调用数。

以下是同机单线程、4 MiB、词表目标 8,000、`min_frequency=2` 的中位数。训练包括初始化、索引、合并和输出；合并列单独计时。完整表、总耗时及峰值 RSS 见 [自动汇总](results/runs.summary.md)。

| 输入 | 当前 HF 训练 / 合并 | 原型训练 / 合并 | PR #2348 训练 / 合并 |
|---|---:|---:|---:|
| 英文，整行 | 10.379 / 8.104 s | 2.896 / 1.391 s | 3.283 / 2.798 s |
| 中文，整行 | 2.528 / 0.875 s | 1.113 / 0.154 s | 0.827 / 0.277 s |
| 英文，空格切分 | 1.315 / 0.644 s | 0.542 / 0.205 s | 0.383 / 0.264 s |
| 中文，空格切分 | 2.204 / 0.494 s | 1.050 / 0.113 s | 0.681 / 0.198 s |

普通配置下，相对当前 HF，原型训练耗时缩短约 **1.93–3.58 倍**。多数配置的完整训练仍慢于 PR；例如 4 MiB 空格切分，英文原型比 PR 慢约 42%，中文慢约 54%。虽然原型在这四组的合并阶段均较快，初始化成本更高，不能仅凭合并阶段宣布胜出。

4 MiB 空格切分的峰值 RSS，英文当前 HF／原型／PR 为 84.9／63.4／36.7 MiB；中文为 183.8／135.1／78.1 MiB。原型比当前 HF 降低内存，但 PR 的连续 arena 更省内存。ByteLevel 使用相同官方 HF 0.23.2 前端；4 MiB 英文总耗时为 3.327／2.711／2.561 秒，中文为 6.283／3.566／2.932 秒。

真实语料计时未设置前后缀、特殊 token 或长度限制，原型实际 ID 复用为零；这些参数的行为由差分测试覆盖，本轮未测其性能。这里测的是相同 feed/train API 的总耗时，不是 v1 尚未提供的 Python tokenizer 级训练入口。数据仅支持这台机器、这些样本和参数下的结论。

## PR 取舍

[PR #2348](https://github.com/huggingface/tokenizers/pull/2348) 当前仍未合并。本轮固定其 head `6ac0de53`，与当前主分支 `bbccb051` 和原型在同一轮测量中比较；PR checkout 保持原样，阶段探针只写入临时副本。

需要将该 PR 作为后续集成的性能基线。原型目前提供了 HF 身份与索引生命周期的适配基础，尚不适合全面替代 PR。阶段数据指出了具体差距：可将其字符初始化和连续存储优化与位置索引结合；精确批次则仍需要重新限定字符串身份复用条件并验证轨迹。
