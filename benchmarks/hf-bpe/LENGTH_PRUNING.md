# HF 长度限制下的更强性质

本文件记录用户要求的独立 subagent 推导，分析当前空 affix 的位置索引路径。已有单调性及 HF 门控证明见 [PAIR_MONOTONICITY.md](PAIR_MONOTONICITY.md)。下述额外内核优化尚未实施；不包含性能测量。

令 M 为 `max_token_length`。HF 有两个不同规则：初始字符 pair 全部登记；合并产生的新邻边仅在左右正文跨度之和严格小于 M 时登记。已选中的规则仍全局执行，并不在具体位置再次判断长度。

## 1. 所有生成 token 的跨度上界

每条选中规则只能来自：

- 初始字符 pair，合并后跨度为 2；
- 已登记的新 pair，合并后跨度严格小于 M。

所以生成 token 的跨度上界为：

```text
L = max(2, M.saturating_sub(1))
```

预留 special ID 不影响上界，它们在语料中首次出现时才具有活跃跨度。

若 M≤256，可用 u8 保存活跃跨度；若 M≤65536，可用 u16。0 仍表示尚未激活。这分别把长度数组从 4 字节/ID 降为 1 或 2 字节/ID，不改变 corpus ID 或 posting 位置宽度。

## 2. 永久阻断的边界

考虑当前相邻两个 token 的跨度 a、b。若：

```text
a+b >= M
且并非初始字符 pair 的例外
```

该邻边不可能成为未来可选规则。合并只能让左右区间变大，不可能让跨度之和重新小于 M；又不能跨过这个边界产生合并。因此这个边界永久保留。

在无 affix 路径中，跨度均为 1 的 pair 是初始字符 pair：新输出至少为 2，未来不能再生成单字符身份。所以判定可登记旧边的完整条件是：

```text
(a == 1 && b == 1) || a+b < M
```

现有 compact 路径仍可能对不满足此条件的旧邻边执行一次必然失败的账本查询。可在查询之前省掉它；不能因为初始 pair 的总长度超过 M 就删除初始候选。

## 3. 永久不能参与后续合并的 token

新生成 token 的跨度为 z。若 `z+1>=M`，任意邻居至少为 1，新邻边全部超限；该 token 又不是初始字符，因此没有初始例外。它永久不能再参与合并。

这支持按选中规则路由到“只扣旧边、不产生出生”的内核。更一般地，一个具体出现位置若两侧都是词边界或上述永久阻断边界，它也永久冻结，即使其跨度小于全局封闭阈值。

### Endpoints 的规则级屏障编码

对于新生成、全部出现均满足 `z+1>=M` 的身份，可以在扣除两侧旧边后，把本来写入 replacement 的首尾端点写成 `NONE`：

1. replacement 从未 live，旧 posting 不可能引用它。
2. 所有新邻边被门控排除，未来候选也不会引用它。
3. 首尾从 replacement 改为 `NONE`，不会让其他候选的端点匹配从失败变成成功；内部历史残留值不变，所以不会产生新的 stale-posting 假阳性。
4. 相邻规则遇到 `NONE` 后省略的，只是未登记屏障邻边的扣减和必定失败的出生。
5. 权重查找仍基于不可变 pivots，不受内部 sentinel 影响。

因此对 Endpoints 核心，这个规则级表示优化有数学证书。它省工作，不缩小 corpus 分配；尚未实现和做工程验证。WordArena 和通用词扫描把 `NONE` 当词边界，不能直接套用；按出现位置冻结较短 token 的扩展也未完成同等实现审查。

### 剩余预算

跨度为 z 的新 token，未来合法邻居最多长 `M−1−z`。邻居只会增大，超过这个预算后该侧永久阻断。若维护当前活跃 token 的保守最小跨度 m，则 `z+m>=M` 也是更强屏障证书；但维护长度分布会引入工作，优先级低于上述静态条件。

## 4. 很小的限制没有出生 pair

当 M≤3 时，任何新输出至少长 2，加任意邻居至少长 3，不满足严格 `<M`。整个训练只消费初始化的字符 pair，不产生任何新候选，生成跨度最多为 2。

因此可选择整个阶段都没有出生逻辑的内核。不过现有代码已经不会在这些配置下增长出生数组；主要新增机会是省分支和账本空查询，不能把它宣称为额外消除了一份已分配的大数组。

## 5. 当前已有与新增机会

| 性质 | 当前实现 | 可进一步做的事 |
|---|---|---|
| 超限新邻边不登记 | 已有 | 不重复计作新优化 |
| 不维护未登记边的负 ghost | 已有 | 提前识别旧边，连 hash 查询也省掉 |
| 旧 pair 单调、低频永久退役 | 已有 | 与长度性质同时成立 |
| 生成跨度上界 L | 仍用 u32 | 初始化一次选择 u8/u16 长度表 |
| 新 token 无任何合法邻边 | 仍走通用 rewrite | 专门的无出生内核 |
| M≤3 全阶段无出生 | 自然不会产生出生 | 整体选择更简单的内核 |
| 规则级所有出现永久冻结 | 未使用 | Endpoints 的 NONE 屏障表示 |

以上是结构与工作量结论。较窄数组和提前判断不保证任何硬件上的墙钟时间必然改善；这里没有追加测试或 benchmark。

长度上界还给出具体合并数量的上界：初始长度为 n 的词最终至少保留 `ceil(n/L)` 个 token，所以具体合并次数最多为 `n−ceil(n/L)`；规则数也不超过所有词此值之和。M≤3 时规则数还不超过初始不同 pair 数。这些界不自动证明批次规则的频率、同频顺序和冲突处理正确。

## 非空 affix 的边界

泛 affix 下不能仅凭出现位置的跨度断言边界永久保留。HF 的门控控制新邻边登记；旧候选扫描整个历史词集合时，仍可能合并同一 ID pair 的超限出现位置。

真实反例：`suffix="a"`、`M=3`、`corpus={"baaba":1}`。初始 `[b,a,a,b,aa]` 选择 `(a,a)->aa` 后为 `[b,aa(span2),b,aa(span1)]`。第一个 `(b,aa)` 总跨度 3，没有登记新边；但初始 `(b,aa)` 候选仍携带这个词，执行它会合并两个位置，得到跨度分别为 3 和 2 的同 ID token。因此普通路径的跨度上界和屏障判定都不能直接用于泛 affix。

M≤3 在任意 affix 下仍没有正出生，但仅凭 signed 账本单调，不能断言 HF 候选优先级也单调：HF 会把负账本转换为 u64。存在旧候选被未登记出现位置的扣减推到负数、随后按巨大无符号频率选中的情况。所以通用路径仍需保留历史账本和候选处理，不能直接删除非正计数。

完整例子是 `suffix="a"`、`M=3`、`corpus={"bbaabbaaba":1}`。规则轨迹为 `(a,a)` 频率 2、`(b,b)` 频率 2、`(b,aa)` 频率 `u64::MAX`：最后一个 key 的 signed 账本从初始 1 扣到 -1，转换后仍被 HF 选中。独立推导使用忠实小脚本核对了这个确定性轨迹；当前通用 Index 保留负账本、历史 cohort 及有限限制下的词扫描，未采用危险剪枝。

不过 M≤3 有另一个安全优化：不会创建任何新候选，因此只需维护尚未消费的初始化候选的 signed 账本。没有初始化候选的 key、以及已消费的候选 key，其后负 ghost 可忽略，也不必保留 map 记录。所有 pending 初始化候选则必须保留，哪怕账本为 0、负数或低于 min_frequency；继续按 HF 的懒更新和无符号优先级选取。这个优化尚未实现。

还可对全部合法装饰解码求静态的角色最小跨度 λL、λR。若 `λL(u)+λR(v)>=M`，该 key 永远没有新的正出生，但仍不能删除 pending 历史候选。更强地，若某身份在两个邻边角色中的最小跨度都至少为 M−1，且 M≥3，它不能是初始 pair 端点，也不能产生任何新候选，可证明该身份永久不可合并；现有通用存储仍不能直接使用内部 NONE。

固定 affix 的身份可逆证书见 [AFFIX_PRUNING.md](AFFIX_PRUNING.md)。通过完整可逆证书时，可恢复普通长度推导；只有 pair 单调证书时，仍需出现位置跨度处理。
