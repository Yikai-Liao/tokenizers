# HF 并行迁移开发计划

## 目标与约束

将 efficient_bpe 主并行机制接入 HF，并定位与原型的额外成本。保留 canonical ID、特殊 token、长度门控及 affix 行为；非空 affix 使用既有 cohort 引擎。posting 采用 u32 地址块；语料 ID 是否采用 u16 是独立选择，构造前检查完整可能 ID 域。开发服务不需要启动。

性能对象是 GB 级真实语料。4 MiB 记录只作为局部诊断，不能代表大规模加速比；AA 人工数据只验证边界算法。初始化空间只在计数、过滤、建堆后核算。

## 1. 原型对照与独立审查

逐项对照主原型源码，不再用“整体对齐”代替清单：

| 项目 | 当前状态 | 检查点 |
|---|---|---|
| 端点 corpus、唯一 pair owner、SmallPosting | 已接入 | 宽度与容量、所有权 |
| 持久 Rayon pool | 每训练创建一次 | 所有批次复用，协调器在 pool 内 |
| 初始化位置路由 → owner 计数 | 已恢复 | 每 worker 连续空间区间一份缓冲，保持位置有序；原型的动态任务游标尚未采用 |
| 初始化低频过滤与建堆 | owner 并行 | 各 owner 独立 retain/建堆，空间统计另计 |
| 分块字典频率与出生安装 | 已并行 | 先按 owner 路由计数；block 并行安装、owner 并行接收目录 |
| 精确批次与 AA 独立批次 | 已接入 | 冲突、频率上界、tie、预留 ID |
| 每 worker 路由、8 字节出生链 | 已恢复 | 不按每 4096 posting 创建一份路由 map |
| AA 跨块奇偶 | 已接入混合边界搜索 | 短链顺查 8 项，长链二分；全链直接判断 |
| 非原子语料写入 | 已接入 | Plan 区间不重叠，split_at_mut，阶段完成屏障 |
| HF canonical 字符串/预留 ID | 必要适配 | 预留输出按单规则处理同频次序 |
| 非原子写入新增空间 Plan/排序 | 原型之外的成本 | 单独计时，依据数据决定后续删减 |
| Halfword/H2.5/H3 串行 ablation | 未迁入 | 不称为主并行已支持 |

独立 subagent 的首轮审查发现初始化小块重复分配、串行建堆、分块计数重复扫描与出生安装串行；均已修复并交回复核。完整结论记录在 REVIEW.md。审查范围包含正确性、并发写边界、遗漏和性能偏差。

## 2. 定位额外成本

阶段计时已加入：tokenize、initial route/count/heap、select、plan、delta、rewrite、commit、route。用总耗时与各阶段对应源码；不凭线程数或理论复杂度判断速度。先核实原型每 worker 结构与当前分配次数，再改变布局。

## 3. 同算法原子对照

显式 atomic_corpus 开关已实现，同一语料、ID 宽度、posting、批次、路由和线程池下比较普通 load/store 与 Relaxed atomic load/store。默认采用非原子。原子/非原子四种存储布局及跨 worker 出生阈值测试通过。核对逐轮 trace 和完整模型摘要，区别“原子访问成本”与“原型共享写入/本版独占切片”的算法成本。

## 4. GB 级真实语料

已从固定 revision 的前两份 Wikipedia 中文 Parquet 读取真实文章段落，准备 1 GiB 原文及来源清单。不得重复拼接小文件或添加随机文本来冒充独立 GB 工作集。根据用户追加的内存限制，首次关键测试取其中约 512 MiB 的完整段落；记录 feed 后不同片段数、实际 corpus N、初始 E 与 alphabet 大小。

依据 alphabet 设置足够的目标词表，确保测量包含实际 merges；基础 alphabet 已超过目标词表时不能拿零 merge 的训练衡量并行。posting 保持 u32。早期访问对照采用有完整 ID 上界证书的 u16 语料；用户要求后的原接口公平比较统一 u32 ID，另行测量。

首次大规模比较仅一个案例：同算法非原子 1 worker、非原子 4 worker、原子 4 worker，各一次，三者已完成且完整模型摘要一致。按用户追加要求，再加入未合并 PR #2348 的固定 head `6ac0de5359d9e0e1ed0608422575a360ef91b908` 的 4 worker 一次对照；保持相同输入和串行 feed，并启用 PR 默认阈值 1000 的条件并行 merge。源码、构建及配置摘要与数据一起保存。

全部算法确定后再做完整 benchmark。按用户最新标准每次监控进程 VmSwap、系统换页、可用内存及 RSS；**仅系统可用内存降至 1 GiB 时停止**，少量进程 swap 可以接受并如实记录。之前把出现 swap 设成停止条件过严，已撤销。测量时不并行运行构建、测试或 corpus 下载。

用户要求的公平控制项：我方增加 `initialization_workers: Some(1)`，保持 merge 4 worker；PR 原样串行计数、4 worker merge。另列我方默认并行初始化作为优化项。由用户指定的 GPT-6 Luna agent 负责关键测试与数据，主 agent 编辑优化；PR 计时结束后才构建/测试。

本次热点优化先改 delta 权重查询：空间有序计划可复用 pivot 游标，同词内直接取权重；跨词先近邻前进最多 8 项，大间隔再二分剩余 pivots，避免每个 plan 从头完整二分，也避免稀疏 batch 全线性扫描所有词边界。独立复核后，仅测新的u32公平控制项、并行初始化项及原子项，各一次。

## 5. 完成条件

- 独立 review 的阻塞问题关闭，剩余差异与原因完整列出。
- 实际代码支持的配置通过逐轮 HF 差分、跨地址块 AA、宽 ID 和大地址算术检查。
- 原子/非原子、1/4 worker 的完整模型摘要一致。
- 报告包含实际阶段时间、工作集、源码/二进制/输入来源及初始化空间，明确容量算术核验与实际 GB 测量的区别。
- 根据真实结果选择入口与布局；实验慢于现有路径时明确记录，不用原型已有的能力掩盖未迁入项。
