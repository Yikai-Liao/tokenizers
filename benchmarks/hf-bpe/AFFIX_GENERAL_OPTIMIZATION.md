# 通用 affix 训练优化

本轮从最佳基线 `48223a58` 派生，源码冻结为 `d7d67475`，工作树位于 `/root/code/tokenizers-worktrees/affix-general`。目标是让任意非空 affix 的兼容实现减少通用成本，同时保持 HF 的有序合并、词表 ID、历史 cohort 和长度限制语义。

## 已实现机制

| 成本 | 改动 | 新增成本或约束 |
|---|---|---|
| 每个字符重复构造装饰字符串和查询词表 | 按字符及原词首尾 flags 缓存已解析 ID | 初始化 Unicode 目录约 8.5 MiB，另加 alphabet 的三个变体；ID 仍按原词遍历首次分配 |
| 初始 pair 计数和位置使用两个哈希表 | 一次 pair 查询同时更新频率和 posting | 建队列时再提取完整账本；保留零权重键 |
| 小 posting 的独立分配及三字段 Vec 载荷 | 复用现有 SmallPosting 的两个内联位置及 arena 策略 | arena 小缓冲在本次训练结束时整体释放，峰值仍须测量 |
| 每次 merge 再找所属词及权重 | 词扫描直接传递权重，位置扫描复用当前词区间 | 乱序出生位置越出缓存区间时仍作精确搜索 |
| 复用未激活或同跨度 ID 时立即分配全语料 span 表 | 只在已激活 ID 的跨度改变时建立 span 表 | 已激活身份复用仍保留历史 cohort 扫描 |

所有变更进入通用 cohort 实现。没有增加 affix 证书路由或使用非空 affix 的单调剪枝；cohort posting 转换成词 ID 及其排序仍保留。

## 正确性和生命周期

完整 lib 测试首次为 69 通过、1 个旧统计断言失败：兼容路径以前未填写 workers，旧断言要求 0。修正为实际单线程及初始化单线程后，该用例单独通过。70 个不同用例均已通过；这不是一次完整 70 通过的运行记录。

覆盖包括原有逐轮 HF 差分、任意 affix、字母表过滤、AA、保留 ID 和长度门控。新增检查覆盖保留 ID 首次激活无需 cohort 扫描的结果，以及本地 arena 在成功、返回错误、panic 后的清理。本地 session 不能跨线程移动；所有 posting 在内部训练函数返回前销毁，之后才释放 arena。

元数据断言复测日志：`/tmp/affix-general-cohort-gate.log`。最初完整运行仅保留工具输出尾部，未保存完整原始日志。

## 首轮测量预算

候选与已完成的最佳基线使用相同原 Trainer 接口、串行 feed 固定哈希种子、语料摘要、release 构建、词表目标和频率阈值。比较 EN16 与 ZH16 的 prefix `##`、suffix `</w>` 和同时开启，共六次候选；完整模型 SHA 必须分别一致。再运行一次无 affix 的 EN16 四线程检查。

ZH512 suffix 使用词表 50000、单线程及 180 秒上限。旧基线已经超时，不能计算精确训练加速倍数。另用一个实际激活身份复用及 cohort 扫描的小输入，比较候选、旧兼容实现和 HF oracle 的完整模型 SHA。

选择依据为完整 train 时间、初始化与 merge 时间、RSS、实际线程数和 posting 生命周期计数。运行期间要求 MemAvailable 大于 1 GiB 且进程 VmSwap 为零。正式计时与编译及测试错开。仅当方向混合或出现具体异常时追加对照；明显改善后转入用户指定的多 block 优化。

## 与无 affix 接近的后续实现

用户进一步明确主要对照是同语料、同线程数的无 affix 训练。第一版的六组小例均与旧 affix 模型 SHA 一致，但仍只有单线程合并；ZH512 在 180 秒超时，峰值 RSS 为 4.91 GiB，高于旧兼容路径的 3.36 GiB。因此第一版只保留为中间候选。

第二版工作树为 `/root/code/tokenizers-worktrees/affix-parallel`，从第一版冻结源码派生。它将一般 cohort 工作按不可变词边界拆分，worker 独占各自的 corpus 与 span 切片，并在词内执行原左到右改写。全体 worker join 后再汇总 signed ledger 和出生 cohort；保留中间产生、后来失效的位置，因为未来的身份复用仍可能使这些历史词 cohort 可见。初始 u16 ID 域复用现有稳定 radix 分组，但保留零频率账本及全部正频率初始 cohort，不按用户的频率阈值剪枝；大 ID 域保持通用哈希计数。

词内邻边更新按规则方向及邻居聚合，只在 join 后按触及的键更新全局账本。出生位置使用八字节链节点，计数后直接填最终 posting，减少每个小出生 posting 的增长分配。单个长词仍由一个 worker 处理，以保持任意 alias 与可变跨度的原语义。小 posting 使用原串行改写，避免为少量位置调度 worker。

默认一般 cohort 分配改用 system；固定 arena 可继续用于已有内部对照。第一版 general arena 会保留多次增长的旧缓冲，而普通快路径通常一次按计数分配，不应直接沿用同一策略后宣称同样的内存收益。

第二版的主对照是 EN16 和 ZH16 的无 affix 四线程，并分别检查 `##`、`</w>` 及同时开启的模型 SHA。先完成完整 lib 检查，再由同一测量代理构建冻结版本；编译与计时错开。ZH512 suffix 用四线程，仍保留 180 秒和资源门槛。直接报告有 affix / 无 affix 的比值及阶段差额；旧 affix 速度只解释优化前后的收益，不替代主要对照。

### 第二版实际结果

第二版冻结为 `65524228234acdc44ce870848632719ad20220c5`。完整 73 项 lib 测试通过；最后新增的私有统计与取消出生分配门控另经三个目标测试复核。六组 16 MiB 模型 SHA 全部与原兼容基线及第一版一致，实际合并和初始化均为四 worker。

| 输入 | prefix | suffix | 两者同时开启 | 同源码无 affix |
|---|---:|---:|---:|---:|
| EN16 | 4.472 s | 4.536 s | 4.300 s | 2.142 s |
| ZH16 | 2.083 s | 2.383 s | 2.082 s | 1.017 s |

ZH512 suffix 已完成：train 86.292 s、峰值 RSS 5.098 GiB；同源码无 affix 为 18.786 s、3.31 GiB。两者均未发生进程 swap。旧 affix 的 180 秒超时没有完整模型 SHA，因此这次大输入的 SHA 尚无旧兼容结果可对照；不得把小输入逐轮差分说成大输入全模型比较。第二版的大输入内存并未改善。

另有 266,154 字节、1024 个独立词的 prefix `ab` 输入，确实激活 ID 复用、cohort 扫描及并行合并。第二版、最佳旧基线和原 HF oracle 的模型 SHA 相同；第二版约 39 ms，无 affix 约 30 ms。小进程的 OS 线程采样不足，实际并行依据私有 worker 统计及并行轮数，而不是声称轮询采到五个线程。

### 第三版正在验证

工作树 `/root/code/tokenizers-worktrees/affix-cohort-scratch` 从第二版派生。阶段计时显示 ZH16 大 posting 的并行改写及提交合计仅约 37 ms；剩余合并成本集中在小 posting 和队列处理。第三版将邻边聚合用于 64–4095 个位置的串行 posting，并复用邻居目录、分组和链节点；每轮只重置触及的邻居，保留全部历史出生位置。超过 4 MiB 的串行 scratch 不缓存。更小的 posting 继续原标量实现，大 posting 继续词边界并行。

这是同一通用 cohort 算法的粒度调整，没有按 affix 内容挑选另一条完整路径。新增缓存域切换与串行尾部 HF 对照检查已通过，完整测试与性能测量尚待完成。新增 serial、selection 和 queue commit 计时用于判断实际节省，不能先把代码改动当作加速结果。
