# 按权重排序并保存区间：实验计划

基点：统一 Bulk(4) 选择策略的 `bpe/validation-window`，源码提交 `bbf25ac4`，连同实验归档提交 `aafb11dc`。候选位于独立分支 `bpe/weight-sorted-intervals`。

## 假设和实现

当前语料构建为每个词保存 u32 起点和 u64 权重；稀疏查询另有每 256 个槽的目录及权重 1 位图。起点只用于查权重，词边界由 NONE 分隔符保留。

在字母表及规范 ID 已确定后，把已有的借用词引用 Vec 按权重降序原地排序。每个工作分区只输出权重变化点，分区合并时去掉相同权重的重复变化点。块内起点和权重 Vec 因而只保存区间，长区间跨块由 previous_weight 传递。平坦路径缓存权重 1 的起点和长度；其它权重二分搜索变化点。该路径不分配空间目录或位图。

排序只移动引用和权重，不复制字符串。使用相同算法处理所有线程数。排序可能改变预取局部性、后续合并的访存排列及各初始化区段负载；这些都属于完整组合的效果，不能只归因于查询变快。等权词无需稳定排序，词内顺序及 AA 的左到右边界保持不变。

## 计时、语义和资源

排序计入 corpus_measure_ms、initialize_ms 和完整 train_ms；corpus_sort_ms 是其中嵌套的计时，不能重复相加。同时记录逐词借用引用的容量、临时变化点容量、保留权重表容量、查询索引容量及全过程 RSS。最终比较在同一 release 二进制中选择原顺序/逐词元数据/位图，或按权重排序/区间/无位图，保持公开 API、依赖、编译参数及 Bulk(4) 相同。feed 为串行，词表哈希种子固定；owner 哈希布局仍随机。

检查完整规范模型 SHA256、单测中的完整合并轨迹、AA、保留 ID、最大 token 长度、过滤后空词、多块长词、零权重、超 u32 权重、u32 全地址范围及所有槽宽度。分配的 posting arena 和堆缓冲必须在结束时全部退还；禁止换页。正式计时与本任务的编译和测试错开。

## 最小测量预算

先跑英文 1 MiB 原顺序/排序两次 smoke。正式中文 512 MiB、英文 16 MiB 四线程各一组对照，共四次；中文单线程一组对照，共两次。若四线程结果小或方向混合且影响选择，只补受影响语料的反向顺序一组。明显失败的组合不扩测；模型不一致立即修复后重跑。需要区分排序及元数据的影响时，才增加排序但保留逐词表的控制组。

保留实测结果和失败事实，报告包括排序的完整耗时，以及权重元数据与总峰值内存的区别。此实验不证明真实数十核机器的表现。

实际扩测依据：中文首轮完整训练改善，但未改阶段也有波动；英文首轮完整训练回退 4.1%，主要发生在提交阶段。中文和英文各补一组反向顺序四线程对照，共四次，检查这两个具体不确定性。

## 第二轮：稳定排序控制

不稳定排序的英文 16 MiB 四线程两组都回退，完整耗时 +4.1% / +11.5%，回退主要发生在合并阶段。这使保留等权词原有空间顺序成为有依据的候选。改用 Rayon 1.12 的稳定 par_sort_by，同样按权重降序；在构造最终语料前释放排序缓冲。显式记录长度乘以 16 字节的排序缓冲容量，小型分块辅助向量另由全过程 RSS 观测。所有线程数仍走同一路径。

先验证语料及完整合并轨迹，再只跑英文 16 MiB 四线程的一组原顺序/稳定排序对照。若仍回退，停止稳定排序变体；若改善，再跑中文 512 MiB 四线程一组对照，确认不会用英文收益换取中文回退。只有决定需要时补单线程。保留第一轮全部实测，原二进制不会覆盖。
