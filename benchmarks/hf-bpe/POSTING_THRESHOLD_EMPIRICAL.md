# 多语言 Wikipedia：posting 长度增长与分配阈值实测

## 结论

本次在真实 J 算法上完成 43 次生命周期诊断：36 次用于拟合、6 次 32 MiB 规模留出验证、1 次 512 MiB 中文留出验证。固定的是实际 4,000 或 16,000 条 merge 规则，全部达到预算。输入规模、预分词、去重后物理规模、merge 进度都会改变分布。

可以在 1–32 MiB 的窄范围用局部幂律粗略预测分位数；**按语料规模等比增加 cutoff 明显过快**。同语言、同预分词、同规则预算的 32 MiB 留出测试，物理边数幂律预测 p50/p90/p99 的平均绝对相对误差为 19.4%/22.0%/17.1%；线性模型为 437.8%/208.3%/191.0%。中位数只缓慢增加。

单幂律无法可靠外推至超大规模。512 MiB 中文的 p90 实际为 31，局部模型预测 91.84；最大值实际 158,054，预测 1,567,308。**当前证据不支持一个跨规模、跨语言的通用 posting cutoff 增长指数。** 更可靠的决策公式是：根据累计出生/退休容量、同时存活容量和阶段余量，选预算内覆盖分配数量最多的阈值。

512 MiB 中文的逻辑容量曲线显示，小 posting 退休后全部保留的成本可以很低：≤32 B 覆盖累计堆分配的 62.06%，终点保留退休空间 19.70 MiB，全程 posting payload 峰值仅增加 5.36 MiB；≤256 B 覆盖 93.30%，分别是 43.53 MiB 和 12.77 MiB。全量保留的退休容量是 477.04 MiB，但诊断中的初始化阶段已经建立整次 RSS 峰值，merge 以后仍有阶段余量。实际候选的 RSS 和速度由独立正式计时验证，本报告不使用诊断 runtime 排名。

## 1. 数据、单位和验证范围

原始数据：[posting-distribution](results/posting-distribution/)，汇总：[bundle.summary.json](results/posting-distribution/bundle.summary.json)。独立拟合、预测和阈值统计：[posting-threshold-empirical-fits.json](posting-threshold-empirical-fits.json)，[复现脚本](analyze_posting_threshold.py) 从这些原始结果重新生成；已核验除耗时字段外全部结果精确一致。理论、预分词静态统计及行尾校正：[POSTING_THRESHOLD_THEORY.md](POSTING_THRESHOLD_THEORY.md)。

拟合输入是 en/zh/de/ja 的 none 模式，以及 en/zh 的 whitespace_split 模式；每种配置使用 1/4/16 MiB、实际 4k/16k rules，共 36 次。32 MiB 的六种配置使用 16k rules，共 6 次；512 MiB 中文 none 使用 16k rules。文本 hash、source path、revision、实际字节数和目标规则数保存在每个 summary。32 MiB 是前缀采样的规模留出；512 MiB 来自更大的源抽样范围，同时存在规模与采样范围变化，不能只把外推失败归因于某一个因素。

这里的 posting length 是历史物理位置数，包含后来失效的位置。p50/p90/p99/max 都按当前存活 posting 的 **type 数量**取分位数，包含内联。Heap-only 中位数另存于 JSON。加权 pair frequency、字符长度、分配 capacity 与 posting length 均分开记录；32 B cutoff 指容量≤8 个 u32，不是 pair frequency≤8。

`E_u` 表示去重片段中的初始物理边数；片段字符长度包含 none 模式保留的 LF/CR。全部 36 个拟合输入的 N/E/U 已与修正后的静态解析精确匹配。目标词表加上各自 initial alphabet，保证比较的是相同实际 M。没有把不同 alphabet 下相同词表大小当成相同 merge 数。

所有 43 次均通过以下资源不变量：

```text
总出生 physical slots ≤ E_u + 2S
累计 heap requested bytes ≤ 16 E_u
累计 allocated bytes − retired bytes = 终点 live heap bytes
growth count = 0
```

其中 S 是成功的物理 rewrite 次数，不乘片段权重。512 MiB 中文为 `E_u=203,230,114`、`S=79,347,366`、`P_birth=346,183,991 ≤ E_u+2S=361,924,846`。累计 heap payload 1,361,236,364 B，即每个初始物理边约 6.70 B，低于保守的 16 B 上界；终点 live 861,028,908 B。

## 2. 长度如何随输入规模和 merge 数改变

### 2.1 中位数缓慢增长，尾部更敏感

下表顺序均为 1→4→16 MiB：

| 配置 | p50，4k rules | p50，16k rules | p99，4k rules | p99，16k rules |
|---|---|---|---|---|
| en none | 4→4→5 | 2→3→4 | 171→307→458 | 69→157→239 |
| de none | 4→4→5 | 2→3→4 | 158→297→496 | 66→157→251 |
| zh none | 3→3→4 | 2→3→3 | 36→62→127 | 15→40→77 |
| ja none | 3→4→4 | 2→3→3 | 42→89→178 | 20→58→112 |
| en whitespace | 2→3→3 | 1→2→2 | 65→99→161 | 21→44→71 |
| zh whitespace | 3→3→3 | 2→3→3 | 27→52→112 | 14→33→66 |

相同输入上更大的 M 会选走更多 pair，也会产生新的小 posting，所以终点分布整体改变。在 1 MiB 英文 none 上，M 从 4k 增加到 16k，p50 从 4 降至 2；16 MiB 上从 5 降至 4。M 对分布的影响还随输入规模改变。这里只有两个 M 水平，不能据此拟合可靠的 M 幂指数或无限 M 极限。

### 2.2 比较三种增长函数

对每个语言、预分词、固定 M，分别在三个规模上拟合：

```text
常数： Q(x) = a
线性： Q(x) = a × x/x_ref
幂律： Q(x) = a × (x/x_ref)^γ
```

全部在 log 空间校准，`x_ref` 为训练 x 的几何平均；`a` 是预测在 x_ref 处的长度。常数固定 γ=0，线性固定 γ=1，幂律用 log OLS 估计 γ。x 分别选 raw bytes 和 E_u。模型最多两个参数，没有给两个 M 水平硬塞多个交互参数。

按 E_u 拟合的局部 γ 范围：

| 配置、M | p50 γ | p90 γ | p99 γ | max γ |
|---|---:|---:|---:|---:|
| none，4k，四语言 | 0.081–0.105 | 0.318–0.409 | 0.356–0.521 | 0.915–1.256 |
| none，16k，四语言 | 0.146–0.250 | 0.485–0.562 | 0.448–0.621 | 1.076–1.455 |
| whitespace，4k，en/zh | 0.000–0.200 | 0.367–0.392 | 0.445–0.523 | 0.917–0.960 |
| whitespace，16k，en/zh | 0.149–0.341 | 0.591–0.591 | 0.570–0.598 | 0.973–1.738 |

这些是三点局部斜率，不是语言自然常数。最大值容易被一两个 pair、merge 顺序或极端片段主导，不能用其较大的 γ 决定所有 posting 的 cutoff。p90/p99 在窄范围约呈次线性增长，p50 更慢。

32 MiB 六个留出配置的平均绝对相对误差（MAPE）：

| 预测量 | 常数、E_u | 线性、E_u | 幂律、E_u | 幂律、raw bytes |
|---|---:|---:|---:|---:|
| p50 | 26.3% | 437.8% | 19.4% | 19.5% |
| p90 | 57.7% | 208.3% | 22.0% | 22.1% |
| p99 | 60.0% | 191.0% | 17.1% | 17.2% |
| max | 92.1% | 44.5% | 49.8% | 50.8% |

在同一语言、同一 PT 的窄范围内，E_u 与 bytes 自身高度相关，所以两者的局部预测误差相近。最大值的线性 MAPE 略低，但幂律的平均绝对倍率误差更低（1.71 倍 vs 1.87 倍）；这说明用一个评分不能把不稳定的最大值模型认定为普遍规律。

### 2.3 E_u 有助于跨语言比较

固定 M=16k、none 模式，每次留出一种语言，用其余三语言的 1/4/16 MiB 数据拟合一个共享模型，再预测留出语言的三个规模。幂律的结果：

| 预测量 | raw bytes MAPE | E_u MAPE | E_u 最坏绝对倍率误差 |
|---|---:|---:|---:|
| p50 | 10.7% | 9.5% | 1.22 倍 |
| p90 | 24.5% | 8.2% | 1.29 倍 |
| p99 | 89.9% | 41.3% | 2.03 倍 |
| max | 314.5% | 119.3% | 5.57 倍 |

物理边数校正了 UTF-8 字节数、去重和片段边界造成的量纲差异，对 p90 很有帮助。尾部仍有明显语言差异；同一个输入特征无法保证极值或整个 CDF 相同。whitespace 模式只测了 en/zh 两种语言，留一语言只能作为两组迁移检查，不能支撑对所有语言的结论。

这支持把 E_u 用作资源模型的基本量。它没有证明预分词、权重和片段长度分布可以省略；它们通过 merge 排名、S/E_u 进度和 pair 出生分布继续影响终点状态。

### 2.4 大尺度留出拒绝通用单幂外推

把 zh none、16k rules 的 1/4/16 MiB 局部 E_u 幂律外推到 512 MiB：

| 量 | 预测 | 实际 | 预测/实际 |
|---|---:|---:|---:|
| p50 | 5.35 | 4 | 1.34 |
| p90 | 91.84 | 31 | 2.96 |
| p99 | 638.90 | 338 | 1.89 |
| max | 1,567,308 | 158,054 | 9.92 |

三个小规模的拟合不足以确定超大规模的幂指数。有限支持、出生/存活混合、不同 merge 进度和源范围都可能改变曲率。作为进度例子，zh none、16k 的 S/E_u 在 16 MiB 为 0.4813，512 MiB 为 0.3904。相同规则条数对应的物理压缩进度不同。可以记录这一无量纲进度；本次没有增加参数拟合它，避免在有限数据上制造一个看似精确的新公式。

## 3. 固定 cutoff 的覆盖与退休代价

这里的覆盖按**整个训练累计堆分配次数**计算，包含后来退休的对象；不是终点分配覆盖率。表中 retired 为把该阈值以下的 buffer 保留到训练结束时多保留的 requested payload，peak 增量为逐分配/退休事件计数的 posting payload 逻辑峰值变化。

| 配置，均 16k rules | ≤32 B 分配覆盖 | ≤256 B 分配覆盖 | 退休保留 MiB：32 / 256 / all | payload peak 增量 MiB：32 / 256 / all |
|---|---:|---:|---|---|
| en 16 MiB none | 64.55% | 93.18% | 2.72 / 7.15 / 107.14 | 0.01 / 0.03 / 70.75 |
| en 16 MiB whitespace | 65.76% | 93.93% | 0.38 / 1.39 / 11.42 | 0.003 / 0.006 / 5.95 |
| de 16 MiB none | 63.41% | 92.87% | 2.37 / 6.35 / 104.37 | 0.02 / 0.05 / 72.53 |
| zh 16 MiB none | 69.27% | 95.93% | 2.21 / 5.58 / 24.15 | 0.23 / 0.50 / 15.58 |
| zh 16 MiB whitespace | 70.11% | 96.24% | 2.02 / 5.11 / 18.83 | 0.17 / 0.41 / 11.35 |
| ja 16 MiB none | 67.30% | 95.18% | 2.32 / 5.93 / 25.92 | 0.25 / 0.72 / 16.58 |
| zh 512 MiB none | 62.06% | 93.30% | 19.70 / 43.53 / 477.04 | 5.36 / 12.77 / 417.82 |

从 32 B 增至 256 B，覆盖通常提高约 25–31 个百分点；全量保留进一步覆盖少量大 buffer，容量增长可能大得多。因此固定 cutoff 并没有在这组大数据上“失去意义”，但其覆盖和资源代价随工作负载改变。

跨全部 43 次诊断，32 B 阈值让 posting payload peak 增加 0.012%–1.881%，中位增幅 0.356%；256 B 为 0.033%–14.240%，中位 1.451%；all 为 47.459%–91.284%，中位 63.947%。这些是**posting payload 峰值**，不能直接当成全程进程 RSS 增幅。尤其小规模、较多 merges 的 256 B 相对代价可明显高于大规模案例，不能给所有配置强行设同一低资源保证。

本组结果说明容量策略有一个覆盖递增、额外保留递增的曲线。容量曲线局部较平坦，尚不能据此宣称训练时间对阈值不敏感；时间还包含 arena/heap 分配成本、chunk 管理、Drop 和 cache 行为，需实际候选计时。

## 4. 生命周期支持什么分配设计

512 MiB、16k rules 的堆对象寿命，按预定义年龄桶统计：

| 容量范围 | 退休 count | 退休 bytes MiB | floor 占退休 bytes | 退休 age≤127 rules 的 count 比例 | 退休 age≥2048 rules 的 count 比例 |
|---|---:|---:|---:|---:|---:|
| ≤32 B | 1,089,563 | 19.70 | 100.00% | 2.78% | 68.44% |
| ≤256 B | 1,420,168 | 43.53 | 约 100.00% | 2.78% | 69.24% |
| 全部 | 1,465,070 | 477.04 | 13.45% | 2.78% | 69.47% |

小对象的大量退休确实存在，但大多数经历了数千条规则才退休。小退休对象主要因为频率跌破 floor，大对象退休 bytes 主要来自被选择的 pair。按容量选 allocator 可以捕捉不同成本来源；只根据“小/大”推测寿命会丢失这种关系。

终点 ≤32 B survivor 中，94.76% 的 count 已存活至少 2048 条规则；≤256 B 为 95.65%。这些对象仍在存活，完整寿命只有下界，不能把观测 age 当成死亡时间来拟合寿命分布。age≤127、age≥2048 只是本次现有桶的描述，未作为新分配超参。

对不回收的 Bump，退休之后造成的成本取决于容量和之后各阶段的余量。对于 small posting，许多退休对象一起只增加数十 MiB，可能无需逐个 free。Pool 能复用它们，但增加管理成本；generational arena 能整代释放的条件是该代全部对象退休。此次生命周期统计尚不能证明 pool、generational arena 比实际 full Bump 更快。

## 5. 用预算得到可审计的阈值

### 5.1 逻辑 payload 的精确事件模型

对于阈值 T，选择小 posting 一直保留、大 posting 原样回收：

```text
P_T(t) = cumulative_allocated_{≤T}(t) + live_{>T}(t)
       = baseline_live(t) + cumulative_retired_{≤T}(t)
peak_T = max_t P_T(t)
```

诊断在每次 allocation/retirement 更新各容量阈值的 current 与 peak；每个阈值使用线性化 fetch_max。这是 capacity 逻辑事件模型，不是某个真实 allocator 的 RSS，且不是多阈值同时读取的一张原子快照。全部 growth=0，对容量 class 边界上的阈值不需要逐对象巨大日志。

如果用户为 posting payload 设预算 `B_p`，可以直接选：

```text
T* = max { T ∈ measured_capacity_bounds : peak_T ≤ B_p }
```

peak_T 随 T 单调，覆盖 count 也单调；因此“预算内最大 T”有清楚的意义。它没有要求 T 必须随 raw bytes 按某个固定函数增加。

例如给逻辑 posting peak 相对 baseline 允许 5% 余量，43 组的最大可行 T 在 128–16,384 B 之间，累计 allocation 覆盖最低 93.76%、中位 98.60%；512 MiB 选择 8,192 B、覆盖 99.79%。允许 1% 时，某些小样本连最小 heap class 都不满足这个严格预算；512 MiB 则选择 64 B、覆盖 78.04%。这是预算函数的示例，不是建议将 1% 或 5% 设为默认魔法常数。

### 5.2 全程 RSS 必须纳入阶段余量

真实用户通常限制整次训练 RSS：

```text
H(t) = memory_budget − baseline_total_resident(t)
可保留条件：额外 resident_arena(t) ≤ H(t)
```

512 MiB 这次诊断，initialize 返回时 HWM 为 4,762,046,464 B、RSS 为 2,530,795,520 B；terminal HWM 未刷新、RSS 为 3,632,267,264 B。初始化返回前建立了整次峰值，之后 merge 的驻留内存仍低于这个峰值。全量退休 requested payload 为 477.04 MiB，小于 terminal 阶段现有约 1,077.44 MiB 的 RSS 峰值余量。

若仅作粗略容量比较，把每个采样点的 baseline diagnostic RSS 加上同一时刻的退休 requested payload，all 相对该 diagnostic HWM 的最小余量仍约 600.41 MiB，32 B/256 B 分别约 1,057.74/1,033.91 MiB。这支持“保留退休对象可能被先前初始化峰值吸收”的判断。

这个加法 **不是候选 RSS 的预测公式**：heap 释放后可能留在页内，arena backing 有增长余量，requested bytes 与被触及页面不同。43 组中只有 17 组 initialize 返回时的 HWM 保持到终点；其他配置的阶段关系不同。微小或负的上述加法余量也不能直接判定候选必然增峰。要验证内存预算，需要实际 allocator 候选运行，并观察全程峰值与阶段 RSS。

因此，不应为了降低 terminal/live payload 就释放所有退休 posting。即使 posting 自身逻辑峰值明显增加，只要发生于初始化大临时数组释放后的阶段余量中，整次 RSS peak 仍可能不变；释放成本却会直接影响训练时间。

## 6. 决策与证据边界

本次推荐保留以下资源式作为可解释的候选策略：

1. 用 `E_u+2S` 的上界和实际累计容量先判断 full arena 是否满足训练预算。
2. 对需要限制资源的输入，根据分桶 birth/retire 与 live 曲线选择最大的预算内 T；阶段余量充足时可以取 all。
3. 只对少数能改变选择的 T 做实际完整训练计时，连同 full-process peak 选型。

局部 `Q≈aE_u^γ` 可以作为观测趋势或短距离初始估计。当前 p50/p90 的语言迁移较好、尾部与长距离外推较差；没有证据支持按最大 posting 长度比例缩放 cutoff，也没有证据支持一个通用 γ。以资源预算作为参数比未验证的语言系数更可解释。

诊断为 PackedPosting 加入出生规则与原因字段，布局从 16 B 增至 24 B，`(u64, Entry)` 是 40 B；还增加 hot atomics、终点精确长度排序与统计数组。诊断 runtime、RSS 和正式 J 的 4.43 GiB 峰值不能直接比较，不能拿诊断耗时评价 allocator。实际 allocator 速度与峰值见 [同 binary 阈值计时报告](POSTING_ARENA_THRESHOLD_REPORT.md)：中文 512 MiB all 满足原峰值，英文 16 MiB all 增峰，因此阶段预算确实随工作负载改变。

独立解析及拟合耗时 1.75 秒，没有执行新训练，没有与正式计时重叠。
