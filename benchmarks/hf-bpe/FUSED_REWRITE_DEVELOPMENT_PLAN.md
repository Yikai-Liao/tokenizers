# BPE 批次融合 rewrite 开发计划

## 目标与基线

将普通 BPE 的匹配校验、邻接 delta 与端点 rewrite 合并到同一次 posting 遍历。AA 与普通规则共用遍历；AA 保留连续段边界调整及左到右语义。整个无冲突批次统一划分任务，线程内按规则顺序处理原有有序 posting，线程间只在整个批次结束时汇总并 commit。

基线固定为 `adb219cda4600e52ea2809d2537ac551c168dd27`，即 `bpe/arena-dynamic-threshold`：纯 Rust Radsort、direct route、packed heap 与每训练一次计算的动态 posting arena 阈值。512 MiB 中文历史计时仅作参考；本次采用同一诊断二进制的基线/候选开关重新对照。

## 已确认的约束

- 切分只读取 posting 地址、数量及规则长度，不读取原始语料确定切分点。
- 不展开全部 u64 地址，不归并或排序整个批次的所有 posting，不保存 corpus 旧值副本。
- 切分调整覆盖邻接依赖；普通短连续串留在一个任务，利用缓存局部性。
- 每条规则由多个 `(block 基址, 局部 posting 子切片)` 组成。局部 u32 地址与完整 64 位基址组合，跨 block 连续段不重置。
- 任务可跨 block；一个 block 也可包含多个任务。出生 posting 按起始位置归属 block。
- 初始 pair、权重、贪心顺序、长度限制、特殊 token 首次激活与全局出生频率门控沿用基线语义。
- 有身份别名的 affix 配置沿用现有串行兼容路径。

## 实施步骤

### 1. Posting 分段与切分

1. 按规则、block 顺序保留原列表，建立少量分段和累计数量元数据。
2. 单规则按逻辑 posting 下标直接定位目标；多规则先试加权稀疏样本估计整个批次的数量分位点。
3. 二分定位每条列表的切分下标，保留给任务使用。
4. 将边界移出所有相交或相邻的潜在合并跨度；原 posting 含 stale，边界判断也覆盖这些跨度。
5. 对 AA 和单规则连续链复用“附近检查 + 二分”的混合搜索，支持跨 block。
6. 记录规划耗时、边界调整工作量及任务 posting 数，实际判断均衡程度与切分成本。

### 2. 共用融合遍历

1. 为每个任务提供独占的语料写区。任务之间无潜在 rewrite 的间隙作为只读借用，不复制旧语料。
2. 线程内按规则顺序直接遍历对应 posting 子切片。
3. 校验当前 pair；读取邻居并生成最终邻接边；立即 rewrite。
4. 识别本批次已经生成的 replacement，避免重复生成邻接边，并用原 head 解读旧边删除。
5. AA 的重叠 posting 在前一次 rewrite 后自然失效；右侧相邻合并直接生成 replacement/replacement 边。
6. 复用线程局部邻居聚合和现有 owner commit；删除中间有效位置表和独立 rewrite 遍历。

### 3. 正确性与资源核验

- 复用全部库测试、HF 逐轮随机差分、独立 greedy oracle。
- 补充分段和 kernel 测试：AA 奇偶、普通相邻及共享 head/tail、stale、不同规则处理顺序、跨 block 连续链、超过 2^32 的模拟基址、非单位/零/大权重。
- 检查任务写区与只读间隙不重叠，跨任务不存在可写邻居访问。
- 检查最终 posting 有序且唯一，arena 分配/退休数量闭合。
- 先保留普通 u32 与 AtomicU32 的同算法存储对照，实际测量后选择；不引入新的逐 posting 原子协调协议。

### 4. 性能对照

最小正式预算：中文 512 MiB 基线、融合 atomic、融合普通 u32 各一次；英文 16 MiB 基线与选定融合版本各一次；generic 多 block 同一输入基线与候选各一次。出现混合方向或小差异影响选型时，针对该项补对照。

固定 feed 哈希种子 `(11,13,17,19)`、输入及参数、4 个初始化和 merge worker、同一 release 二进制和动态 arena 策略。记录源码提交、构建 overlay、二进制摘要、输入摘要、模型摘要、实际布局、完整 train/initialize/merge、规划与融合阶段耗时、任务分布及进程峰值 RSS。正式计时不与编译、测试或其它 CPU 重任务并行。

最终以完整 train API（包括 posting 与 arena 释放）的速度判断收益，merge 阶段解释来源。峰值取内核 HWM 与采样 RSS 最大值；沿用 MemAvailable 低于 1 GiB 停止与进程无 swap 检查。单独列出切分成本、负载均衡与新增元数据。

### 5. 缓存与并行空泡诊断

用户补充要求：除端到端速度外，评估是否提高缓存命中、减少并行空泡；缓存无法可靠评估时明确记录不可评估。

- 先核验 perf 权限与实际硬件事件。若可用，在相同 posting 工作量下记录 cache references/misses、cycles、instructions，优先补充可靠的 L1/LLC 事件；保存 multiplex 比例和事件定义。不把通用 cache-misses 直接解释为所有缓存层的命中率。
- 记录每个任务的 posting 数、开始/结束时间及并行阶段窗口，计算任务分布与 worker 有任务执行的时间比例。这个比例包含内存等待，不等同 CPU 忙碌比例。
- 记录 merge 阶段各 worker 的线程 CPU 时间，区分任务等待、负载不均与主线程规划/汇总。CPU 时间比例本身不能证明某一种等待原因。
- 详细任务时间或 perf 诊断另列调用及开销，不混入正式速度排名。只有观测直接支持时才报告“缓存命中改善”或“空泡减少”。

## 交付与状态

### 追加：出生片段使用规则和邻居直接汇总

512 MiB 中文 v2 对照中，空间任务输出的 delta 分组片段由基线 57,835,113 增至 91,036,137；融合版 commit 6.316 秒，基线 5.794 秒。用户进一步要求提高 commit 速度。

对于 flat 且 token ID 数不超过 65,536 的既有邻居聚合路径，按 `(规则, 左/右方向)` 保存出生分组，owner 使用单个邻居 ID 目录跨任务汇总。出生 key 的新身份确定所属规则；两侧均选中的边界由左侧规则产生，所以同一个 key 不跨桶。目录按桶复用并只重置触及项，避免 `规则数 × 词表` 存储。旧边删除表与高 ID/generic 路径继续沿用当前实现。

可省操作是任务出生 flush 的哈希入表及 commit 出生片段的临时哈希查询；代价是分桶向量、邻居目录、分组重置和片段链。先通过全库差分及 CDAB/规则换序/跨任务全局门控测试，再做同二进制基线与候选各一次 512 MiB 对照；只有直接阶段与完整训练方向支持才继续验证英文及存储选型。诊断调用和源码版本分别保存。

计划已写入；融合代码在隔离分支 `bpe/fused-aa-rewrite` 开发。完成后提交源码、可复现构建/运行脚本及中文性能报告。只有正确性通过且完整指标支持的版本才标记为推荐版本；保留失败候选及实际完成的调用记录。


## 完成记录

统一融合遍历在代码版本 `fa693488` 完成并通过全部 68 个库测试。按阶段事件定位了遍历与 commit 的额外访问；缓存比例和 worker 利用率的改善未被解释为净收益。

出生 commit 优化独立移植到原实现，代码版本 `a0f58018`，分支 `bpe/dense-birth-commit`，全部 64 个库测试通过。独立 release 中文 512 MiB 完整训练 21.029→19.307 秒，commit 5.754→4.099 秒；英文 16 MiB 完整训练 2.285→1.953 秒。选用旧遍历与出生 commit 优化的组合，融合版本保留作为实验。

实际完成 44 次训练调用，其中 25 次正式对照、11 次非诊断模型检查、8 次诊断。全部模型、posting 生命周期和进程无 swap 检查通过。具体来源、范围与英文/generic 混合结果见 [FUSED_REWRITE_REPORT.md](FUSED_REWRITE_REPORT.md)。
