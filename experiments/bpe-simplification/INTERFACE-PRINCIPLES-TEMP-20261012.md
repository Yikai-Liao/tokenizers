# BPE 模块接口整理原则（临时）

本文件用于本轮接口调整与独立审视。范围仅为普通 BPE 训练目录；Parity Trainer、WordPiece 及其他训练器和外部调用方不在本轮修改范围内。基线为 `2f74a832`，保留现有模型结果、错误语义和并行阶段关系。

## 从 Positions 改动得到的标准

原来的 `tasks() -> ReadTask` 要求调用者先接收任务对象，再调用 `.iter()`；merge 还需要 `Source::Slice / Task` 适配两种来源。现在 `chunks()` 直接返回可独立消费的标准迭代器，merge 接受位置流，两个自定义概念随之删除。restart 对齐、起始 leaf 定位、读取边界、目录和 codec 均由 Positions 内部维护。

这种封装的价值是：模块提供完整能力，调用者减少必须理解的规则、维护的状态和配合执行的步骤。代码数量是结果证据；文件搬家、压缩写法或给原有步骤增加包装，不能单独证明简化。

## 调整原则

1. **追踪一条真实调用路径。** 写清调用者现在必须知道什么、哪些改变会要求多个模块同步修改，再决定边界。不能仅根据函数长度、文件大小或方法数量找问题。
2. **实现决定归实现所有者。** Corpus 提供语料与 ID 数量等事实；index 决定计数表示和阈值；Positions 维护位置流的排序、重复值和存储规则。调用者独有的业务选择仍由调用者决定。
3. **提供能直接完成任务的能力。** 优先消除调用者的装配循环、转换、缓存状态和先后协议。接口应能说明输入、输出、所有权及成立条件。
4. **优先标准迭代器与直接所有权转移。** 能以 `impl Iterator`、切片和现有容器表达的能力，不额外引入任务类、服务、trait 层次、`Box<dyn Iterator>` 或解压后的中间 Vec。必要的混合来源可在内部用现有 enum 组合。
5. **一次移动必须有连带收益。** 新接口落地后检查调用侧是否真的删除了概念、状态或内部知识；纯移动可以改善知识归属，但应明确其收益，不声称因此减少了实现复杂性。
6. **保留语义上必要的区别。** 新身份与历史身份复用、AA 与普通规则、整体有序连接与交错流归并、删除与出生事件都有不同契约。相似代码不能成为强行合并的理由。
7. **保留完整的并行阶段边界。** 所有 preparation 读者完成后才能写入；所有写入完成后才能发布 index。错误仍丢弃整个 attempt，不增加回滚承诺，也不让惰性读取越过阶段边界。
8. **保留可验证的性能机制。** 本轮接口调整保留 restart 定位、16 项预取窗口、固定跨度缓存、权重区间缓存、片段顺序和无重编码连接。不得靠封装引入额外分配、排序或全量扫描；性能主张需要实际证据。
9. **检查完整使用与失败路径。** 空流、重复坐标、full-u64、片段交错、过期候选、零权重出生、逐事件溢出、跨任务邻接和身份复用都以现有契约为准。
10. **同步权威说明。** 代码、模块 README 和 DESIGN 应描述同一套当前接口及表示；历史实验报告保持历史事实。生产代码、测试和文档的增减分别看待。
11. **收敛公共接口。** 模块用少量完整入口服务真实调用任务，避免调用者通过多个取值或动作方法重建能力。总是配套使用的参数、输入与状态在所属模块内部绑定；端点、目录、缓存和布局读取优先私有。新增公开入口须说明现有入口为何不足，不能靠把每段内部操作公开来实现封装。接口数量是线索，实际验收看调用义务是否减少；必要生命周期和业务决定仍应可见，测试诊断入口只在测试构建中暴露。

## 当前保留的调整

- Positions 使用标准位置 chunks，并拥有有序连接和交错流归并；调用方不重建存储协议。
- Corpus 的 fresh reader 保留已有 Match／权重输出、16 项预取窗口及固定跨度和权重区间缓存；matcher 内部读取 token，取消调用者把同一 token 传回的步骤。
- CorpusPlan::initial_chunks 绑定初始 edge 流与词数，ranges/edges 私有；PairIndex 在计数成功后更新进度，自己选择 dense/sparse 表示和当前 pool 的 owner 数。plan 提供统一 fresh/reuse 事实。
- Alphabet 从当前 pool 决定 presence 分块；内部 ID 查询、Alphabet 字符表和 Priority count 只保留必要的测试诊断入口。
- builder 直接持有 BpeTrainer，默认值只定义一次，删除 Config 镜像和 build 的逐字段装配。
- Vocabulary 拥有已提交的 ID 规则历史。merge 在 index 发布成功后追加规则和测试 trace，只返回完成量；协调者不维护历史 Vec 或 MergeRecord 装配循环。记录分配仍存在，不主张因此减少了分配。
- Neighbors 构造时初始化自己的目录，删除调用者预先 resize 的协议。

## 撤回的设计与剩余问题

9287b3d8 引入了公开 Neighbor、CohortMatch、FreshMatch 和 Cohort。虽然几何查询移入 Corpus，merge 仍需解释这些输出并装配计数事件、starts 和 Job，公共概念和字段反而增加。不能以 Corpus 本体方法减少认定模块变深。当前删除这四种新增公开类型，恢复原有直接 preparation，保留已有 Match／权重协议和私有 CohortPreparation；没有将相同数据改名为新 tuple 或 enum。

之后尝试将 merge 变成 Corpus 私有子模块，仅改变了归属、可见性和访问关系，没有消掉实际装配。用户指出这一点后，整项未提交改动已撤回；Corpus 与 merge 仍是独立模块，完整轮入口仍是 BpeTrainer::merge_next。

最新独立审视按完整 feed→初始化／计数→fresh/reuse preparation→写入／发布→错误／重试／零 merge→输出核对，未确认能同时删除这些输出类型和实际装配的可靠完整 prepare 方案。已有几何耦合仍然存在，本轮不宣称完成了 preparation 的深模块改造。直接按候选坐标划分完整 word 并持续推进 cursor，可能删除 words Vec 和逐词 seek，但会改变分块／负载机制，尚无足够证据支持实施。

## 验证范围

- 默认／无默认配置库测试各通过 41 项，包含 64 组输入在 1/4/8 worker 下的独立模型／规则对照。已删除专为被撤回 cohort reader 编写的测试，保留原有 preparation 和完整模型验证。
- 两种配置均沿用此前范围，跳过既有 tokenizer_roundtrip 用例；这不是全部库测试通过的声明。
- cargo clippy --all-targets 通过，使用 -D warnings -A clippy::redundant_field_names，沿用已有 lint 例外。
- 本次两个 Rust 文件通过项目 formatter 检查；git diff --check 通过。
- 本次未运行 Miri 解释器或性能实验，不主张训练加速。

## 独立审视要求

每次发现有证据且值得实施的新问题，处理后启动不继承前轮结论的 fresh 审视者；未确认新候选时结束循环，不制造问题。审视只读，不改文件、运行重型实验、发布变更或扩大普通 BPE 训练范围。每项建议必须指出实际能删除的概念、装配或状态，以及仍须保留的行为和成本。
