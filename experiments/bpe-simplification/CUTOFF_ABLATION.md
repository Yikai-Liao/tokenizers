# Arena 阈值输入消融

结论：保留 resident slots 输入。九个 case 中八个落在 256 字节下限，两种输入得到完全相同的分配阈值；唯一阈值不同的中文 256MiB 样本不足以支持额外保存 physical edges。

消融固定源码 `378fd5d6`，使用同一个不可变 binary，通过环境变量只改变阈值输入，算法、样本、线程和编译参数相同。实验副本增加 edge 统计字段；交付版本没有这个字段。当前版本延续相同语料几何和阈值公式。4 workers、CPU0–3、ByteLevel、50K 词表、min_frequency=2。

`T(N) = max(256, floor(sqrt(N / 256)))`，N 分别取初始物理边 E 或 resident slots S。对于这些非空 plain word maps，S = E + 2W + 1，W 是去重后的词数；不能假定所有语料的相对差距都小。

42 个已记录进程均完整模型一致、child swap0。九个 main 进程提供语义参考；成对比较使用两种阈值输入都有结果的重复，排除中文 16MiB 的孤立 edge 第二次结果。七个 case 各两对，中文 16/256MiB 各一对；没有把未完成的第三轮计入统计。

中文 256MiB 的阈值为 859 与 890 字节。slot 单次 wall 高 2.04%、RSS 高 4.29%；样本量为一对，且其他 case 在阈值完全相同的情况下也有 wall/RSS 波动，因此不能把全部差值归因于 31 字节阈值差。这里没有稳定收益证据来抵偿新字段和贯穿计划的额外状态。

RSS 为公开 train 结束、序列化之前的进程 HWM，包含输入加载，不是 Arena 专属占用。原始记录、输入 hashes 和不可变 binary 留在 `/root/code/tokenizers-simplification-results/cutoff-ablation/`；紧凑证据见 [cutoff-ablation-summary.json](evidence/cutoff-ablation-summary.json)。
