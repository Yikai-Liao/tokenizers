# Positions：编解码封装、重启目录收敛与双元素内联

> 修订：撤回 Segment 命名方案。对外只保留容器操作与分片迭代器，不新增可见的存储/调度对象。

## 目标与依据

沿用当前已经验证过的在线追加、指数扩容重启目录和 Leaf/Root 结构，降低理解成本。将两个实现改动分别提交、分别验证，再据实测作出采纳决定：

1. 收拢编解码和布局责任，整理分段接口命名。
2. 用已有的首值与末值缓存表达两个元素，避免第二次追加时溢出到堆。
3. 根据测量结果决定是否保留第二项，不把结构整理和性能实验混为一个结果。

参考分支：`Yikai-Liao/tokenizers` 的 `simplify/bpe-flat-20261010`。本计划核对的分支头为 `3436bba7f9603147f8ead3ffacc0a91b6c4b05ab`；相关生产实现见 [890ea1f 的 positions.rs](https://github.com/Yikai-Liao/tokenizers/blob/890ea1f58e65f8d8503f7cd3fc97ad1651eaf284/tokenizers/tk-train/src/trainers/bpe/positions.rs)。实施前核对后续提交，保留已落地的修正。

这是源码审查后的实施计划，没有执行仓库代码或验证性能。本文中的收益估计只涉及可直接推导的存储变化。

## 历史接口对照：继承原则，不恢复旧的泄漏

[9f5b553d 的无 enum 版本](https://github.com/Yikai-Liao/tokenizers/blob/9f5b553dba61dba45a75021f4292997c16359dfb/tokenizers/tk-train/src/trainers/bpe/positions.rs#L189-L298) 使用 `Positions(Box<[u8]>)`。它已有标准 Range/Iterator 读取接口，但 `block_ranges`、`read_blocks` 仍公开了块编号，构建还依赖 Input、Lease/Codec。不能将这版整个搬回。

[02620e0 的后续版本](https://github.com/Yikai-Liao/tokenizers/blob/02620e0ad37d8b165b5923902a05184e483cbd88/tokenizers/tk-train/src/trainers/bpe/positions.rs#L145-L221) 已把读取边界收敛为 `partition_ranges` 与 `iter_range`，范围表示元素下标，外部无需命名一个 Task/Chunk 对象。这是本次应继承的设计原则。

新版 Root 持有多个叶子。直接恢复全局元素 Range，再分别调用 iter_range，会丢失当前已经定位好的起始叶子：朴素实现每个任务都从头累加叶子长度，最坏产生“任务数 × 叶子数”的定位工作；另加前缀目录则增加存储和维护责任。本计划两者都不引入。

因此本次提出适配 Root 的不透明分片迭代器：内部保留直接起始叶子引用，外部仍只操作迭代器。它是新表示下的接口调整，不声称历史代码已有完全相同的签名。也不新增按任意第 k 项访问的通用需求。

## 一、接口与职责

### Positions：容器语义

保留追加、拼接、顺序读取、按值起读和分段读取。外部不需要知道目录、编码字节、重启块、缓存位置或临时构建状态。

删除对外的 `ReadTask`，不再另起 `Segment` 或 `Chunk` 包装类型。使用分片迭代器语义：外层迭代分片，每个分片直接是可迭代的位置序列。方法可沿用熟悉的 `chunks(target_len)`，但不能让名称暗示它返回内部压缩块。

接口形状如下，具体生命周期按项目 Rust 版本落实：

```rust
fn chunks(&self, target_len: usize)
    -> impl Iterator<Item = impl Iterator<Item = u64> + Send + '_> + '_;
```

`target_len` 是目标大小，实际切分可在内部对齐，不承诺精确等长。对外注释只说明覆盖完整序列、顺序不变、各片不重叠且可独立消费；内部注释再说明重启对齐和小叶子组合。不要把内部重启块大小作为调用者必须知道的参数。

外层只创建轻量借用迭代状态，不解码全部坐标，不为每片分配 Vec 或 Box。叶子、目录与分段边界状态均私有；不因为 Rust 需要保存状态就暴露一个新的领域类型。

具体的 `Send`、生命周期和嵌套 `impl Iterator` 签名须由实施时的编译检查确认；这里给出接口意图，不冒充已通过编译的补丁。

当前 merge.rs 用 Source 枚举保存切片或 ReadTask，再调用 prefetched。同步将它改成消费普通坐标迭代器：自对切片使用 `iter().copied()`，普通位置使用 chunks 的内层迭代器；混合任务容器可在内部用已有 `itertools::Either` 统一两种迭代器类型。`prepare_job` 接受泛型迭代器，原预取逻辑接收并消费该迭代器，不依赖 Positions 的实现类型。删除原 Source 枚举；预取逻辑可以成为消费泛型迭代器的私有函数。保留原有任务 Vec、顺序收集和 Rayon 分发，避免额外引入调度改造。

需要单独核对一个成本：任务 Vec 若从“叶子切片、起点、长度”改为保存完整迭代状态，每项描述符可能变大。记录实际类型大小、任务数量和 Vec 容量，计算增量；不能因没有单独 Box 就声称零内存开销。必要时以私有惰性状态推迟解码器初始化，但不得为此再造公开视图类型。

不为省掉一个类型增加动态分发、坐标物化或一串转发函数。若具体签名或生命周期有编译问题，在内部适配；不能回退为重新公开 Task/Segment/Chunk。原 ReadTask 若还能作为私有实现状态复用可以保留，但调用者不可命名或依赖它。

### Leaf：存储与完整追加操作

保留现有两个字段：`SmallVec<[u8; 16]>` 和 `NonZeroU64` 编码长度。Leaf 负责：

- 字节存储、容量增长与分配错误。
- 首末值、长度与有序性不变量。
- 重启目录的位置、容量、有效范围与搬移。
- 从校验、预留到提交的完整追加事务。
- 根据目录创建从指定重启点开始的读取游标。

不新增持久化的 Storage、Layout、Directory 或 Builder 对象。不让调用者执行“先准备，再写入，最后补长度”的多步协议。

### 私有 codec：字节格式与解码状态

将手写的整数编码循环、解码循环和读取游标放进 `positions` 内的私有 `codec` 模块。可以使用 `positions/codec.rs`，模块只对父模块开放所需接口，不能被其他 BPE 模块直接调用。

建议只保留以下能力，名字可随现有惯例微调：

| 能力 | 责任 |
|---|---|
| `gap_width(gap)` | 返回完整 u64 的 LEB128 编码长度，零占一个字节 |
| `append_gap(bytes, gap)` | 将一个差值写入已经预留好容量的存储，内部维护编码循环 |
| `read_absolute(bytes)` | 按既有小端格式读取绝对值，供首值和重启点搜索复用 |
| 私有 `Cursor` | 从重启点开始，统一解码绝对值与后续差值，实现 Iterator |

这里的模块封装是为了集中格式规则，不需要可实例化的 `Codec`、`Scratch` 或泛型输出 trait。`append_gap` 可以直接接受现有 SmallVec 类型；一个内部用途不值得换成通用编码框架。

编码器不选择容量增长策略，不访问 Leaf 长度和目录，不自己做第二次可失败的 reserve。Leaf 在调用编码器前一次性预留足够容量。内部契约可以用局部 `debug_assert!` 检查，但仍使用安全的写入操作，不为省掉边界检查引入 unsafe。

绝对值写入若只是一次 `extend_from_slice(&value.to_le_bytes())`，可留在完整追加操作中。不要为“所有字节操作必须经过一个对象”增加无实质责任的一行转发包装。编码循环、解码循环和格式解释必须集中。

`gap_width` 与 `append_gap` 的一致性是预留空间正确性的基础：实际写入字节数必须等于声明宽度。解码保持当前“读取内部合法字节流”的契约，不扩展成面对任意外部损坏输入的公共解码 API。

`RESTART = 128` 的格式规则只保留一处定义，由目录与游标共同使用。目录条目属于存储布局，不塞进整数 codec。

## 二、重启目录的封装

### 名称表达真实含义

- `directory_bytes(len)` 改为 `reserved_directory_bytes(len)`：当前计算的是目录预留容量，不是有效条目的字节数。
- 去掉含义不明确的 `head()`，以 `data()` 返回实际编码数据切片。首值读取、游标初始化和重启搜索复用它。
- 写入路径中需要旧、新布局时，使用局部 `old_data_start`、`new_data_start`，避免一串没有语义的偏移量。
- 当前长度、下一长度与 `len + 1` 编码值分清命名，避免把逻辑长度和 niche 编码混用。

`data()` 有非空叶子的前置条件。空叶子的 `cursor(start == len)` 必须先返回空游标，不能先计算并切出从第八字节开始的数据。`restart_before` 也保留 `groups <= 1` 时直接选择第零个重启位置的分支，不提前访问 `data()`。

### 保留一个完整的冷路径

保留 `push_restart` 作为完整操作：

1. 校验顺序、长度和所需大小。
2. 计算目录增长和绝对值写入所需空间。
3. 一次性 reserve，失败时不修改逻辑内容。
4. 必要时搬移数据并初始化新增目录空间。
5. 写入重启条目和绝对值。
6. 更新末值缓存和长度。

这些步骤可以在一个清楚的函数中按顺序展示，不拆成互相依赖的 grow、relocate、finish 调用。尤其不要让冷路径返回时字节布局已经改变、长度却仍是旧值，再要求外层补交状态。

普通差值追加保持短而直接：校验差值 → 计算宽度 → reserve → codec 写入 → 提交末值和长度。不要仅为合并两处最终赋值而增加协议或热点分支。

### 必须就地说明的三个规则

1. 目录条目保存相对数据区起点的偏移。因此整体搬移数据区后，不需要逐个改写原有条目。
2. 目录容量按重启块数量的二次幂增长。并非每追加 128 项都搬移整个数据区，也不能将其描述为二次复杂度。
3. 只有一个重启块时没有实体目录；有目录后，第零条目为零。搜索只看有效条目，不能把预留的空白容量当成真实重启点。

保留搜索的严格小于比较与回退到前一重启块的规则，确保跨块重复值不被跳过。不要顺手把它改成普通“大于等于目标的首个块”。

## 三、双元素内联：独立性能实验

### 表示方式

当前 16 字节内联区由八字节末值缓存和八字节首值占满，所以基线仅一个位置能无分配存储。第二个位置再写一个差值就会溢出。

两个位置实际上可由同样的 16 字节完整表达：

- 长度一：首值与末值相同。
- 长度二：首值是第一个元素，末值缓存是第二个元素，不再存重复信息的第二项差值。
- 长度三及以上：恢复现有绝对值加差值的字节流格式。

长度已经能区分这些情况，无需增加 One/Two/Three 枚举或持久化字段。不影响重复位置是否合法：`[x, x]` 仍由长度二区分，不能把相等误判成长度一。

### 追加的状态转换

第二次追加完成既有长度、有序性检查后，只更新末值与长度，不分配。

第三次追加需要补写两项差值：原末值减首值，以及新值减原末值。各自宽度为 1–10 字节，必须在修改任何内容前，一次性 reserve 两者的总宽度。随后依次编码，最后更新末值与长度。

禁止先写第一项，再进行第二次可失败的 reserve。否则第二次分配失败会留下长度为二、字节流却已改变的半完成表示。这个转换完全藏在 Leaf 的一次 push 中，不新增 freeze 或 finish 协议。

分支限制在追加入口的短长度处理，不把二元素判断重复塞进普通编码循环。可以调整条件排列，但不承诺编译后没有新增指令；实际检查热点代码与性能。

### 读取方案：优先复用现有终止分支

一个值得先实现的低侵入方案是在私有 Cursor 中增加：

```rust
pending_tail: Option<&'a [u8; 8]>
```

只有二元素叶子从头读取时，正常字节流指向首值，`pending_tail` 指向末值缓存。现有 `bytes.is_empty()` 分支中，若 pending_tail 存在就取走并返回一次，否则结束。普通非空数据的解码循环不新增二元素判断。

其他游标初始化为 None。`start == len` 必须直接构造真正的空游标，不得附带尾值。返回尾值后维护游标原有的索引、当前位置约定；再调用 next 必须返回 None。

代价需要明确：在常见 64 位布局下，游标通常多一个八字节可空引用，并增加初始化与流结束时的判断。它不增加 Leaf/Positions 的持久化大小，但可能扩大 flat_map、分段迭代器状态。不能把“普通解码循环未新增条件”说成“完全零成本”。

若此方案实测或可读性不合格，再比较无分配的标准迭代器组合；不同时保留两套读取实现，也不引入动态装箱。不要用魔法索引值伪装解码模式。

### 收益边界

恰好两个元素的叶子可省掉一次 spill 分配与 1–10 字节差值。一个元素没有新增收益；三个及以上最终有效编码字节回到基线格式。

第三次追加合并预留两项差值，容量轨迹可能与基线两次独立 reserve 不同，即使保留同一增长公式也不能保证容量相同。

“81.6% 的非空叶子有 1–3 项”不足以推断本优化覆盖率。应单独报告恰好两项的数量，以及有多少叶子只是暂时经过两项后继续增长。

## 四、验证与提交安排

### 提交 A：纯结构整理

完成 codec 封装、目录命名与读取边界整理、删除对外 ReadTask 并改用分片迭代器。保持字节格式、增长策略、叶子分配行为和分段语义；任务迭代器的描述符大小另行核对。

确认任务创建仍只建立借用状态，未提前在协调线程解码或预取；既有 Source 只消费一次，不要求内层迭代器可重复读取。

复用现有测试，对比编码字节、顺序读取、按值读取、分段拼接结果。确认其他模块不能依赖私有 codec/Leaf。生产代码与测试代码分别统计行数；不要靠移动文件或压缩排版宣布维护成本下降。

### 提交 B：双元素内联

在 A 上实施二元素表示和完整的第三次转换。复用现有测试框架，以少量参数覆盖：

- 空、一、二、三项；重复值；零与完整 u64 最大值。
- `[0, u64::MAX]` 与继续追加 `u64::MAX`。
- 第二、第三次非法逆序追加后，原内容仍能正确读取和继续追加。
- 127/128/129、255/256/257 等既有重启边界。
- 二元素叶子参与 concat、chunks、iter_from_value，包括等值边界。
- 连续 next 到结束后仍返回 None。

当前重复值样本中，长度二的存储断言应从 17 字节且 spilled 改为 16 字节且 inline；长度三仍为 18 字节且 spilled。确认 64 位目标上 Positions 仍为 32 字节，单独记录 Cursor 的实际大小。不要把推测布局当测试结果。

沿用现有错误保持测试，不新造庞大的分配失败测试框架；若已有可控分配失败设施则补上第三次转换的失败点，否则明确这一项来自源码不变量审查。

### 性能对照

复用现有语料与计时流程，至少覆盖中文 Whitespace 和中文 ByteLevel；沿用现有英文样本作为补充。先用已有单 worker、6 workers 设置，正常构建各做两轮，交错顺序；排名不稳定时再补测，不预设每场景五轮。

分别比较原基线、A、A+B：

- 正常训练耗时、CPU 时间、峰值 RSS，模型完整一致性。
- 短列表分配次数和二元素占比，作为单独诊断运行。
- 若回退，检查追加、游标初始化/结束、读取与释放阶段，不把总体变化直接归因于某一个 if。

诊断计数不混入正式计时构建。不要通过全局换分配器或限制 allocator arena 来掩盖产品版本的内存回退。

## 五、完成标准

- 调用者只理解位置容器和标准迭代器操作，不需要组装编解码对象。
- 字节编码规则集中，目录布局规则集中，追加操作保持完整。
- 不增加持久化描述符字段、递归 Root、通用构建器体系或公开压缩块概念。
- 一个叶子的 concat 仍直接返回叶子，不额外分配 Root。
- 纯结构整理可独立合入；双元素优化只有在完整正确性和时间/内存结果明确后采纳。
- 交付简短结果：删掉了哪些需要调用者理解的规则、生产代码净变化、测试变化、真实测量与仍未验证的部分。
